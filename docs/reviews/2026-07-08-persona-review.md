# The Blue Board — Persona & Code Review (v2.0 Readiness)

**Date:** 2026-07-08 · **Method:** multi-persona hands-on review + five-domain code audit + independent fact-checking research + adversarial verification of every "broken / incorrect data" claim.

## How this review was done

- A local harness served the full dashboard with realistic mock APIs (seeded scenario: EWR ground stop + thunderstorms, ORD GDP, equipment swaps, ~351 live flights), so every tab could be exercised hands-on with Playwright.
- **Seven personas** used the site in character: a nervous once-a-year flyer, a 1K/2-million-miler, a United network-ops analyst, a mobile-only user (iPhone geometry), a keyboard-only low-vision user (with axe-core sweeps), an aviation-data fact-checker (against an independently researched July-2026 fact base), and an indie-product growth strategist.
- **Five code auditors** covered: schedule/timezone correctness, live feed/IROPS/delay-risk/AI, pipeline resilience & cost, frontend runtime/XSS/PWA, and security/compliance/README drift.
- **All 93 broken/incorrect-data candidates were adversarially re-verified** by independent agents instructed to refute them, with production config (Vercel `cleanUrls`, `.env.example` source priority, upstream kill-switch states) taken into account. Results: ~85 confirmed (some with corrected severity/mechanism), 1 refuted, 1 reclassified as a dev-only artifact.
- Baseline health: `bun run test` 942/942 green, `tsc --noEmit` clean, production build works. Mock-data numbers were out of scope; rendering/logic/labeling of that data, and all static content, were fully in scope.

Finding IDs (F001…F093) refer to the verified-findings appendix at the bottom.

## Part 1 — Fundamentally broken or giving incorrect data

These are verified, production-relevant defects. Grouped by theme; each item names the root cause and the fix direction.

### 1.1 The disruption story lies during actual disruptions (the site's core moment)

The dashboard's whole identity is "see United like an ops center." During the seeded ground-stop scenario, its surfaces contradicted each other — and the code paths confirm this happens in production:

- **IROPS understates active ground stops** (F073, high). `api/irops.ts` counts a flight as delayed only once it has a real departure timestamp; flights *held on the ground* — the definition of a ground stop — contribute zero delay while still inflating the denominator. Result observed: "MINOR DISRUPTION" headline during an EWR ground stop, one point short of the ≥15 "SIGNIFICANT" threshold. Fix: treat past-scheduled-but-not-departed flights at a hub under an active FAA program as delayed (or add a program-severity term to the score).
- **Hub health chips are green during a ground stop and rank the GDP hub as worse than the ground-stop hub** (F046/F076, high). Chips are backward-looking OTP-of-operated only; no FAA program signal is blended in — the ticker two inches away says "Disrupted: EWR ground stop" while EWR shows 🟢 84%. Fix: chips take `max(otpColor, faaProgramColor)` exactly like `ops-health.js` already does for the ticker.
- **Arrivals-board OTP is mathematically wrong** (F021, high). `board-stats.js:65` compares scheduled *arrival* against real *departure* — a 90-minute-late arrival scores as on-time (probe-verified: otp=100 vs otp=0 with the direction fixed). Every arrivals board's stat strip is inflated garbage that contradicts the DELAY column on the same rows. One-line fix + the missing arrivals test coverage.
- **The IROPS panel has two competing writers** (F002, high). `updateIrops()` (client, partial-board recompute, mixes directions/days, counts estimated delays) silently overwrites `renderIropsFromAPI()` (server, all 9 hubs) after every board load — cancellation counts visibly flap (151→9→151) and the ticker's ≥15 advisory gate flaps with them. Same bug class v1.5.26 fixed for OTP ("single writer") — apply the same rule to IROPS.
- **Dual concurrent FAA programs render garbled** (F074, high). `main.js:3823-3833` only special-cases `ground_stop`/`ground_delay`; EWR's simultaneous `departure_delay` falls through to the bare reason string: "⚠ Ground Stop until 1049Z · ext: high, thunderstorms ↑ Increasing", and the real delay window (46–180m) never renders. The correct formatter already exists in `delay-explain-context.js` — reuse it.
- **The NOW divider files still-held flights under "the past"** (F075, high). `main.js:5162` anchors the divider (and time sort) to scheduled times only, so a 2-hours-late, not-yet-departed flight sits above "── NOW ──" as if resolved — precisely during GDPs, when it matters. Use `max(scheduled, estimated)` for row placement.

### 1.2 Flagship features that are structurally dead

- **"Where's My Plane" / Aircraft Journey / inbound-turnaround risk never work** (F001/F010, high — two auditors independently). Every consumer treats `/api/flight-times`' `aircraft` field as a tail number, but all three provider tiers return an aircraft *type* string ("Boeing 737-900"), which then fails `aircraft-history.ts`'s registration regex and can never match a live-feed tail. The marquee v1.5.0 feature, and the 28-point inbound signal in the risk engine, are unreachable. Fix: return a real `registration` field per tier (FlightAware and FR24 both have it) and key everything on that.
- **Equipment-swap detection is dead under the documented production config** (F025, high). `api/_schedule-aerodatabox.ts:263` hardcodes `model.code: ''`, and `detectEquipmentSwaps` requires a truthy code — with `.env.example` saying `SCHEDULE_SOURCE_PRIORITY=provider` in production, swaps silently never fire on provider boards (and the aircraft-type filter dies with it). Also: swaps are blind to same-type config changes — a 46J high-Polaris 767-300ER subbed for the 30J standard bird shows nothing (F050), and the localStorage baseline is overwritten every fetch so a detected swap vanishes on reload. This is the feature the community press singled out — it deserves a registration/config-aware, persistent implementation.
- **The AI delay explanation is always told the risk score is 0/100** (F011, high). The client posts `el.dataset.riskScore` (a string); `delay-explain.ts:128`'s `typeof === 'number'` check zeroes it. Every AI briefing reasons from "score 0/100" while the modal header shows the real score. One `Number()` fix.
- **Flight-watch alerts can't fire when the tab is closed or backgrounded** (F031/F049, high). The change-detector runs only on manual foreground schedule loads; the 30s poll stops on `document.hidden`; `sw.js` has no `push` handler and there's no push-subscription endpoint. The watch feature's implicit promise ("we'll notify you") is not being kept — this is both a bug today and the #1 v2.0 feature (see Part 3).
- **Check-a-Connection can say "SAFE — Comfortable connection" about a cancelled flight** (F003/F014, **critical**). No cancelled/diverted check, and missing gate times produce NaN math that falls through to the green verdict. It also asserts padded numbers as fact — "75min minimum required" at ORD when United's published domestic MCT is ~40–45 (F055). This is the single worst wrong answer the site can give; gate the verdict on data presence + cancellation status, and label MCT numbers as comfort guidance.
- **Fleet table SEATS column is blank for all 1,078 rows** (F051, high). `escapeHtml()` returns `''` for non-strings; `fleet.json`'s `tot` is a number. `String()` it first.
- **Fleet WiFi data contradicts the Starlink tracker for 88 of 90 equipped mainline tails** (F052, high — independently recounted). `fleet.json`'s `w` column still says ViaSat/Ku for tails `starlink.json` lists as equipped, and the static fleet-type pages derive their Starlink story from `w` alone — undercounting ~90 real installs to near zero on pages that are otherwise July-2026 fact-checked. The fleet pipeline needs a Starlink overlay join.

### 1.3 Search — the front door — fails the most common visitor intent

- **"UA 1234" with a space fails, and the placeholder itself suggests that format** (F042, high). Raw query with space is matched via `.includes()` against space-free callsigns. The failure message then asserts "UA373 is not currently airborne" — false.
- **Scheduled (not-yet-airborne) flights are invisible to search until the user has manually visited the Schedule tab** (F043, high). `schedAllFlights` is lazily populated. A visitor Googling "is my united flight delayed tomorrow" — the site's most common cold intent — dead-ends by design. Fix: search should query the schedule API (or preloaded boards) directly and say "tomorrow, scheduled, on time" instead of "not currently airborne."
- FR24 fallback lookup shows whichever leg of a flight number is active with no date/route disambiguation (F048, medium) — label the leg and date.

### 1.4 Data-trust presentation

- **Flight popup mixes timezones** (F047/F054, medium): departure time renders unlabeled in the *viewer's* timezone next to an arrival labeled UTC; the tz-populating tier (FlightAware) is exactly the one usually bot-walled, so this is the normal case, not the edge.
- **`/api/flight-times` has no date dimension** (F005/F013, medium): tomorrow's watched flight resolves to today's/yesterday's completed leg — cards show green LANDED for a flight that hasn't left, and the risk badge is suppressed.
- **Stale data is stamped LIVE**: complete boards get a 6h CDN pin with zero staleness signal, defeating the hourly IROPS warm (F037, high); the service worker replays cached API responses as HTTP 200 which the client stamps LIVE (F032, medium); METAR backfills from a never-expiring last-known-good store with no age marker (F040, low).
- The My Flights Starlink badge sticks on "⚡ Checking…" forever — the journey re-render wipes resolved badges and never re-fetches (F045/F053, medium).

### 1.5 Money and cost exposure (owner-facing "broken")

- **Paid FR24 Official API is reachable by background refreshes with no data-age gate** (F036, high) — the AeroDataBox path has a >3h + cooldown gate; the official-API path has only a 1h freshness check and an env kill-switch that defaults ON.
- **`flight-times` / `fr24-flight` / `aircraft-history` bypass the shared 402 quota block entirely** (F038, high) — a credit-exhausted account keeps getting hit (this matches the 402-spam incident in your own changelog).
- The warm cron alone consumes ~96% of the default AeroDataBox daily budget, and the client's idle preload wastes further units fetching *yesterday's* ORD/DEN boards 24/7 due to an ET-anchored timestamp (F022, medium — same mislabeled-day class v1.5.16 fixed in the cron, surviving in the client).

### 1.6 Content correctness (real pages, verified against July-2026 primary sources)

- **"9 hubs" vs reality** (F058, **critical** for SEO): United's FY2025 10-K lists **eight** hubs; NRT is a gateway. Your own v1.6.1 fix corrected `/fleet` to "eight hubs + Tokyo-Narita gateway," but the welcome modal, homepage copy, **FAQPage + ItemList JSON-LD** (which feed Google/AI answer boxes), `llms.txt`, `llms-full.txt`, README, and `feed.xml.ts` all still say 9. Pick the editorial line ("8 official hubs + the NRT gateway we also track") and sweep every surface.
- **EWR page lists Tel Aviv as an active transatlantic route** (F060, high) while your own March news article reports it suspended (through ≥Sept 7, 2026 per the fact base).
- `/fleet` contradicts itself on-page: stat card + JSON-LD say **430** Starlink aircraft; the FAQ and copy beside it say **425+** (F059, high). README still says **258+** and "Inter" fonts (F062/F041). Fleet totals (1,078) and A321neo (62) are internally consistent but are Q1 snapshots presented as "mid-2026" — actual is ~1,100–1,115 and ~70 (F061/F064, medium/low).
- fleet.json contains no A321XLR and no 222-seat Elevated 787-9 config, both of which your own fleet pages describe as flying (F056, medium); the 767-300ER page says 203 seats where its own data row sums to 199 (F057, low).
- The Sources page claims "METAR observations and TAF forecasts" — no TAF exists anywhere in the app (F077, medium).
- The TSA page's email gate promises "we'll let you know the moment checkpoint wait times return" while the code comments call the MyTSA feed decommissioned (F068, high) — an unkeepable promise attached to email collection.
- Two different unsourced social-proof numbers in one funnel: modal says 22,000+ users, welcome email says 25,000+ (F069, medium).
- *Refuted for fairness:* the DEN-Polaris-omission claim was wrong — the lounge is announced-but-unbuilt, and the DEN page is correct by omission (F063).

### 1.7 Mobile and accessibility lockouts

- **Landscape first-run lockout** (F090, **critical**, pixel-verified): at 852×393 the onboarding card renders 671px tall, the dismiss button sits 69px below the viewport, the overlay doesn't scroll, and backdrop taps pass through (`pointer-events:none`). A user who opens the site in landscape cannot enter it.
- **The news banner sits on top of the Live map's controls on mobile** (F091, **critical**): the mobile CSS pushes every tab down to clear the banner *except* `#tab-live` — the filter toggle and each popup's close button are underneath it (clicks time out). Default tab, every visitor with an unread banner.
- **The desktop About/Donate/Supporters popover is invisible** (F065, high): `#tab-bar`'s `transform` makes it the containing block for the `position:fixed` `#legalpop`, which renders under the map. This is the **only** dashboard surface linking to the Supporters Wall, membership, privacy, and attribution — on a donation-funded site. (The same element is also an invalid `<details>` child of `role=tablist`.)
- **The welcome modal declares `role=dialog aria-modal=true` but has no focus trap and ignores Escape** (F79, high): keyboard focus leaks into hidden background links; the backdrop-click handler is dead code because of the same `pointer-events:none`.
- **Keyboard dead-ends on core flows** (F080–F085, high): search results, sort headers, tail-number links, the AI risk badge (the marquee feature), and map hub-filter rows are all unfocusable spans/divs — while the *correct* pattern (`role=button` + `tabindex=0` + the existing global Enter/Space handler) is already applied to `.phase-row` one widget away. Applying the app's own pattern to ~6 selectors fixes most of it.
- The hub-health "?" explainer loses all its a11y attributes on the first data re-render (F087), and the tooltip explaining the header percentages is `display:none`'d dead CSS — the most prominent numbers on the page are defined nowhere (first-flyer + a11y agreed).
- Real-but-narrower offline bug found while refuting the "PWA is broken" claim: the precached `/index.html` is a redirect-followed response Chrome won't use to fulfill navigations, so offline fallback only works for the exact cached `/` URL (F088 nuance). The dev-server `start_url` 404 itself is **not** a production bug (F089, dev artifact).

## Part 2 — Polish

Friction that's cheap to fix and compounds trust:

1. **Explain the header numbers.** "ORD 76%" has no visible definition (the tooltip was deliberately hidden). One always-available legend fixes the most-asked question on the page.
2. **Jargon layer for normal humans.** IROPS, OTP, METAR, GDP, "38M", tail numbers — the nervous-flyer persona catalogued a dozen unexplained terms. A tooltip glossary (and plain-language labels like "Irregular ops (IROPS)") keeps the NOC aesthetic while onboarding civilians.
3. **Search forgiveness**: strip spaces before matching, accept "ORD to DEN", link search dead-ends to the Schedule tab / fleet record instead of asserting "not currently airborne" / "not found."
4. **Click-through from search results** should land on the row (scroll + highlight), not just switch tabs.
5. **Timezone labels everywhere a time renders** — one `fmtTime` that always says which clock it's on.
6. **Provenance chips**: "as of 7:12 PM · via schedule snapshot" on flight-times data (the 3-tier fallback is invisible today), and an age chip whenever SW/CDN/last-known-good data is served.
7. **Waitlist modal**: split the two competing CTAs (email vs donate), retarget the trigger (8 clicks/90s interrupts a first-timer mid-search — fire on the *flight-landed* moment that's already wired at main.js:7796 instead), and drop the "Pro features coming" paywall leak until that's a real announcement.
8. **Mobile**: promote My Flights out of "More" (swap with Fleet); make markers ≥14px hit targets or add hit-slop; sticky table headers; a right-edge fade to signal horizontal scroll; `viewport-fit=cover` + safe-area insets; real maskable icons; tablet layout between 600–1024px.
9. **Consistency batch**: one user count (22k vs 25k), "Fonts" and Starlink counts in README, `0%` → "n/a (small sample)" on filtered utilization, "—" vs 0 on IROPS cancellations, capitalization of provider statuses, per-page OG images (one static og-image.png everywhere today), double opt-in on waitlist emails, remove the dead `#bmac-toast` handler.
10. **A11y quick wins** (beyond Part 1): focus outline on the header search (currently `outline:none`), aria-live="polite" on the ticker only, labels on map markers ("UA123 ORD→DEN, cruising"), fix heading order (h1→h3 skips), Escape closes the filter drawer, keyboard-focusable scroll containers.

## Part 3 — Larger features (the v2.0 thesis)

Research context that frames these: seats.aero proves ~$10/mo willingness-to-pay in the United-nerd niche (gate depth, never the core); Flighty gates all push alerts (its #1 complaint) and is iOS-only; ExpertFlyer carries **no** United upgrade/award inventory; SeatGuru is dead (Oct 2025); EWR is FAA-capped through **Oct 2027**; Starlink hits ~1,000 aircraft by year-end; and every airline-vs-hobbyist lawsuit (SWMonkey, Air Canada v. seats.aero, United v. Cooperstock) was triggered by monetization or trade-dress, not by existing.

**Tier 1 — the killer feature set (do these first):**

1. **Server-side flight watch + real push/email alerts.** The current watch is dead when the tab closes (F031/F049). Move watches server-side (Supabase table + a cron that diffs statuses + Web Push via the SW `push` handler and/or email via Resend). This single feature makes the PWA worth installing, powers everything below, and is the proven freemium axis (email free / instant push+SMS for supporters).
2. **Equipment-swap alerts across the network.** The clearest unmet demand in the entire United community — United doesn't notify, ExpertFlyer has no UA data. Requires fixing the swap pipeline first (F025/F050): registration/config-aware detection, persistent baselines, premium-cabin delta framing ("764→788: −16 Polaris"). Watch a flight, a route, or a fleet type.
3. **"Where's My Plane" done right, free, on the web.** Fix the registration pipeline (F001), then render the full inbound chain with ETAs. Flighty charges ~$50/yr for this on iOS only; a shareable web version is a press-magnet differentiator.
4. **The EWR Crisis Center.** A dedicated `/newark` page: live cap utilization against the 72 ops/hr order (through Oct 2027 — a *durable* story), ground-stop status, today's cancellations, historical trend, plain-English "what it means for your flight." The media re-tells this story weekly; own the SEO for it. Generalize later into per-hub disruption pages.
5. **History.** Nightly OTP/IROPS snapshots per hub (you already snapshot schedules) → 7/30/90-day trends, meltdown timelines, "which hub should I connect through" charts. FR24 gates history behind paid tiers; a UA-specific archive is the natural supporter perk that takes nothing from free users.

**Tier 2 — depth for the personas you now know:**

6. **Starlink prediction + a `/starlink` landing page** ("will MY flight have it": fleet %, route history, tail-swap risk) — after resolving the upstream permission (below). The fleet.json/starlink.json join fix (F052) is the foundation.
7. **TAFs + delay-cause attribution.** Add TAF fetch/display (fixes the false Sources claim, F077) and an hourly "why" strip per hub (ATC vs weather vs cascade — the delay-risk engine already has the signals; F078's unscored en-route TMIs included).
8. **Ops-grade stats**: completion factor, D0/A14 by hub, cancellations timeline, bank/wave visualization at IAH/ORD/DEN (the ops persona's top asks) — replacing some snapshot eye-candy.
9. **Morning Ops Brief email.** The onboarding modal already collects a home hub and throws it away (localStorage only). Home hub + waitlist email + existing Resend pipeline = "your 6am ORD brief." Free weekly / daily for supporters (the Cranky Flier ladder at hobbyist pricing).
10. **Per-flight and per-route pages** (`/flights/ua123`, `/routes/ord-den`): SEO surface for exactly the queries that bring cold visitors, powered by data you already have; each with proper OG images.

**Monetization — the sequence matters (legal research was unambiguous):**

- **Phase 0 (before any money moves): compliance.** Replace the FlightAware HTML scrape (spoofed-UA, against ToS) with licensed AeroAPI or drop it; get written permission for the Starlink upstream (or build first-party detection) — your flagship differentiator currently rides on a robots.txt violation and *cannot* be part of any paid tier (F072); confirm your FR24 API tier covers a public commercial dashboard; set the CAN-SPAM postal address; keep visual distance from United trade dress. Monetizing first and licensing later is the exact pattern that got SWMonkey and seats.aero sued.
- **Phase 1: donations, properly plumbed.** Fix the invisible donate surface (F065). Contextual asks at gratitude moments (the flight-landed trigger already exists — point it at a dedicated "glad you landed ☕" card, not the acquisition modal). A public **cost-transparency meter** powered by the real signals in `api/fr24-usage.ts` + `_cost-state.ts` ("Today: 340/400 board refreshes used — supporters keep this live"). One-tap Apple Pay/Venmo amounts. Surface the Supporters Wall. Wikipedia-style capped appeals with "I already donated."
- **Phase 2: supporter tier ($5–8/mo), gating depth never core:** instant push/SMS alerts (email alerts stay free), history beyond 7 days, the morning brief daily, saved multi-flight watchlists, API access. Free tier keeps: full live map, boards, current-day data, swap banners, email alerts. That line preserves the fan-project goodwill that is both your moat and your legal shield.

**Foundation (make truth cheap):**

- **Single source of facts**: one `src/data/facts.js` (HUB_COUNT/HUB_LIST, STARLINK_EQUIPPED + as-of date, FLEET_TOTAL, per-type counts) imported by every page, JSON-LD, llms.txt, and README template — with a CI grep that fails the build when a hardcoded number bypasses it. This single change would have prevented the entire F058/F059/F061/F062 class.
- **Dev/prod parity + integration harness**: the SW/PWA was untestable locally (three agents tripped on it); a `vercel dev`-faithful local mode and a mock-API fixture layer (like this review's harness) would let you regression-test disruption scenarios, arrivals OTP, and the swap pipeline. Add arrivals-board tests (zero exist) and a "single writer" invariant test for IROPS like the one you wrote for OTP.
- **Spend guards**: unified 402 quota block across all FR24 callers, an age gate on official-API background refreshes, and fix the client preload's yesterday-board burn.

## What's genuinely excellent (keep doing this)

- The **ticker never falsely says "normal ops"** during a disruption — the ops-health derivation is the right architecture; extend it to the chips and IROPS panel.
- The **delay-risk engine's inbound-turnaround math** (haversine ETA vs required turn time, inbound-origin weather) is genuinely sophisticated — "better than most paid tools" per the ops persona — it just needs its registration plumbing fixed.
- **Swap banners with cabin-impact chips** ("Lost Polaris", "+16 seats") — exactly the right product framing; nobody else does this.
- **Technical SEO is best-in-class for the niche**: full JSON-LD, per-page FAQs, llms.txt, Google News sitemap. Content pages (hub/fleet) are accurate to a level that impressed the fact-checker (EWR cap timeline, Polaris Studio details, GUM Island Hopper stops all check out).
- **Honest engineering culture**: the changelog documents failures candidly, statuses admit inference ("Departed*"), disclaimers are everywhere, tests are real (942), and the correct patterns (Escape handlers, role=button+tabindex, single-writer OTP, antimeridian normalization) exist in the codebase — most fixes here are "apply your own existing pattern to the neighbor that missed it."
- The mobile Starlink board's card layout, the ARIA-correct main tab bar, real `<table>` semantics, `prefers-reduced-motion` handling, and self-hosted fonts all show unusual care for a solo project.
